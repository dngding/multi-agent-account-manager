# 从现有本地代理池选择账号代理

> 日期：2026-11-22
>
> 范围：Windows 功能分支的新选择器。代码已接入；这项新增功能的 Windows CI、WebView2 实机以及真实代理池链路仍待验收。此前 `4dce77d` 的验收和安装包不包含该选择器，不能作为本项通过证明。

如果电脑已经运行 Telegram Panel 等工具使用的 Mihomo 固定端口池，可以直接复用其本机入口，不必为了叠号重新导入机场订阅或再运行一个代理客户端。叠号只读本地代理池 YAML，从可识别的固定入口中供用户选择，然后沿用每账号代理预检和后台保护。

## 1. 最少操作

1. 在 Windows 叠号中点击“新增”。默认进入“从现有代理池选择”，打开弹窗时立即读取最新列表。
2. 在下拉框中选一个入口；可用名称或端口搜索。**不会自动选择第一项，也不会自动分配所谓空闲代理。**
3. 填写账号备注，选择“仅保存”或“检查并打开”。仅保存可以不选入口，账号仍为待配置；选定入口的待激活账号也需手动打开才创建网页。
4. 编辑已有账号时，点击其网络图标。原来从池中绑定的账号会显示对应选择；原来手动填写地址的账号仍显示手动方式，不会因端口恰好相同就被认作池绑定。

列表显示本地端口和可读名称，例如：

```text
Muse A → socks5://127.0.0.1:7891 → 现有池中的固定静态节点
Muse B → socks5://127.0.0.1:7892 → 现有池中的另一个固定静态节点
```

这里的端口仅为格式示例，不能据此认定端口存在、可用或无人占用。选择并不会修改 Telegram 的账号绑定，也不会从其账号手中“释放”或“抢占”端口。

## 2. 未自动找到来源时

展开“代理池来源”：

- 自动发现只扫描当前用户 `WorkBuddy` 下符合日期格式的一级目录，查找 `telegram-panel/flclash-sidecar/sidecar.yaml`，不递归扫描全部磁盘。
- 只有一个候选来源时可自动读取；发现多个来源时不自动决定，需从候选文件中选择并点击“应用来源”。
- 也可以输入现有本地 YAML 文件的**绝对路径**，然后点击“应用来源”。不要填写订阅 URL、目录或节点 URI。
- “自动发现”只重置本应用记住的来源选择，重新列出候选；不改动代理池文件。

来源选择保存在叠号自己的数据目录 `proxy-pool-source.json`。默认 Windows 数据根通常为 `%APPDATA%\com.ldjx.accountmanager\`；测试使用 `DIEHAO_DATA_DIR` 时，来源设置随该测试根保存。账号所选来源、入口 ID、目标定义指纹和显示名称随账号记录保存。

测试进程可以用 `DIEHAO_PROXY_POOL_FILE` 显式指向合成代理池文件。设置该变量时不自动发现生产来源，也不能从界面切换来源；无效显式路径不会回退读取其他池。

**来源文件只读。** 叠号不会写回 YAML、导入或更新机场订阅，不会调用 Panel 认证/API、修改 Telegram 账号、重启 Mihomo，或启用系统代理、TUN、防火墙。应用只写自己的来源选择和账号绑定。

## 3. 哪些入口可以选择

当前选择器按本地配置识别下列入口：

| 配置形式 | 选择器行为 |
| --- | --- |
| 无认证的 `http` / `mixed` listener，直接指向顶层静态节点 | 生成本机 HTTP 代理地址 |
| 无认证的 `socks` listener，直接指向顶层静态节点 | 生成本机 SOCKS5 代理地址 |
| 本机回环监听；或来源中的通配监听 | 客户端保存为本机可连接的回环地址，不修改原监听范围 |
| 动态 provider、代理组、`DIRECT` / `REJECT` 等非固定目标 | 不作为可选固定节点入口 |
| 需要入站认证、非本机入口或其他不支持的形式 | 不生成可用候选；配置冲突或解析失败时明确报错 |

这不是完整 Mihomo 配置编辑器。列表为空时，先核对选中的来源和入口结构；不要为了让条目出现而直接改动正在服务其他账号的生产代理配置。

## 4. 更新如何同步

弹窗打开时立即读取；打开期间每 **10 秒**复查一次，窗口重新获得焦点和点击“刷新”也会复查。代理池新增、移除或修改条目后，可选范围随新读取结果更新。同步保留账号备注、手动地址、搜索和未应用的来源草稿，不把第一项补成选择。

| 变化 | 处理方式 |
| --- | --- |
| 新增符合要求的入口 | 出现在最新下拉列表，等待用户选择 |
| 原选入口删除、变成不支持的形式，或同端口目标定义变化 | 取消当前有效选择并提示重新确认；不能直接提交旧选择 |
| 来源文件丢失、不可读或 YAML 损坏 | 清空可选列表并提示错误，不用旧缓存假装正常 |
| 更换选择器的默认来源 | 影响后续选择范围，不自动改写其他账号已保存的来源和入口 |
| 已绑定账号的原来源、入口或目标定义失效 | 后端在打开、复用、预热及运行复核等路径重新校验；不自动换节点，发现失效时阻止对应账号继续使用并显示状态 |

选择保存时同时提交来源、入口 ID、目标定义指纹和代理地址，后端再次读取来源验证一致性；不能只凭前端还显示着某项就接受已失效绑定。列表同步与运行复核是周期性应用层检查，不保证文件变化瞬间停止所有网络流量。

恢复配置后应重新确认列表与绑定，再手动打开。不要通过删除绑定或清空必需代理来绕过错误；需要代理的账号清空后仍会被阻止打开。

## 5. 占用和重复提示怎样理解

- “本应用 N 号已用”统计叠号本地账号，包含不同服务中使用相同本机端口或保存相同目标指纹的账号；编辑时不把当前账号算作自己的冲突。
- “同目标 N 入口”提示本次配置中多个入口指向同一个固定节点目标，不能把它们按端口数当成不同出口。
- **Telegram 占用未知。** 当前没有接入 Panel 的账号占用 API，因此不会显示“TG 未用”“空闲”或自动分配未用目标。
- 目标指纹用于比较节点定义是否变化和提示重复，**不是公网 IP、设备标识或独享出口证明**。不同端口、节点名称、服务器地址也可能共享公网出口。

## 6. 手动地址与解绑

切换到“手动地址”可以继续填写完整 `http://主机:端口` 或 `socks5://主机:端口`。选择此方式并保存后，账号的池绑定会清除，只保留手动地址，不再跟踪原 YAML 中的入口删除或目标变更。

仅切换选项卡而未保存不会修改账号。手动方式仍沿用代理格式校验、连接预检、后台健康检查和必需代理限制；它不接收机场订阅链接或内嵌用户名/密码。

## 7. 当前验证边界与待验收清单

本功能校验的是**本地文件与保存绑定的一致性**。它不能证明正在运行的 Mihomo 已重载这份文件、监听与文件完全一致、代理可到达 Muse、节点公网 IP 独立，或 Telegram 没有使用该目标。文件更新完成与服务重载完成必须分别核验；不要只凭下拉列表变化判断实际流量已换节点。

新增选择器的 Windows CI 和实机结果当前均为**待验收**。后续应使用合成来源和未登录测试账号，分别验证：

1. 初次打开、单来源自动发现、多来源显式选择和手动 YAML 路径。
2. 新增、移除、改目标后，10 秒、焦点恢复和手动刷新均更新列表；备注、草稿及焦点保持。
3. 删除已选项、修改同端口目标、来源丢失和坏 YAML 后，不接受旧选择、不自动改选。
4. 保存时后端重读能拦截前端刷新之后发生的变化；已绑定账号复用和后台复核同样受约束。
5. 手动保存清除池绑定；其他账号仍保留原来源；重复入口和本应用占用提示准确。
6. 用独立测试代理确认服务实际重载、网络可达和停止行为；再另做浏览器公网出口和泄漏验收。

既有按账号代理基线与限制见 [开发指引](muse-multi-account-isolation-development-guide.md) 和 [2026-11-21 状态验收报告](windows-proxy-setup-state-acceptance-2026-11-21.md)。没有现成固定端口池时，再参考 [机场订阅接入指引](airport-subscription-proxy-setup.md)；无需为了使用选择器重复部署一个生产代理服务。
